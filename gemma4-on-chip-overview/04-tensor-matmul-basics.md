# 2560 个数进入一层：先把矩阵乘这笔账算清

[系列索引](README.md) · 第 04 期

上一章停在一枚 token 的 2560 维向量。它已经能承载模型学到的语义线索，但还没有回答用户的问题。接下来的 decoder 会一层层改变这条向量。若一上来就把 42 层画成一张大图，线会多到看不清；先跟住其中一次最常见的变换，就能看懂后面各条支路的形状和代价。

设一枚 token 的输入为 `x:[D]`，权重为 `W:[D,N]`，输出为 `y:[N]`。第 `j` 个输出是 `y_j=Σ_i x_i W_{ij}`。也就是说，输入的每个数都参与了第 `j` 个结果的计算，只是对应的权重不同。求和让 `D` 轴消失，产生新的 `N` 轴；输出的一个数不是输入中某个数的简单复制。

拿构造数字算一次：`x=[2,3]`，`W=[[1,4],[5,6]]`，于是 `y=[2×1+3×5, 2×4+3×6]=[17,26]`。这不是 Gemma 4 的权重，只用来说明“一行输入乘同一张矩阵”究竟做了什么。若输入有多个位置，公式扩为 `X:[B,S,D] × W:[D,N] → Y:[B,S,N]`：`B` 是请求数，`S` 是 token 位置数，每个位置独立应用同一张权重。位置之间的通信还没有发生。

## 形状能告诉我们哪一种工作变多

把 `B×S` 暂记为 `M`，一次矩阵乘就是 `[M,K]×[K,N]`，需要约 `MKN` 次乘加（MAC）。有些算力口径把一次乘加算作两个 operations，所以下文出现 TOPS 或 FLOPS 时会注明口径。对 E4B 一张 `2560→10240` 的投影，一枚 token 对应 `2560×10240≈2621 万` 次 MAC；128 枚 token 对应约 `33.55 亿` 次 MAC。工作量随位置数变多，但同一张权重也能在这 128 行之间复用。不能仅凭乘加数断定后者的耗时一定是前者的 128 倍。

这里也容易和代码里的矩阵方向对不上。本文把数学权重写成 `[K,N]`，方便看到 `K` 被约掉；PyTorch `nn.Linear` 通常把参数存成 `[N,K]`，前向相当于使用它的转置。两者描述的是同一次线性变换，不能拿存储形状直接当运算输入形状。

`shape` 还只是逻辑信息。`[B,S,D]` 若以 BF16 存放，原始字节数是 `B×S×D×2`；若是 FP32，就是乘 4。实际峰值内存还要加权重、暂存结果、缓存、对齐与双缓冲。一个张量有多大，也不等于它一定从外部内存完整读过一次。接下来的硬件分析会把**算多少**、**存多少**、**搬多少**分开。

## 并非每一步都是矩阵乘

线性层改变特征宽度；逐元素激活只改变对应位置的数值；RMSNorm 要沿特征轴求均方根，再缩放这一组特征；残差把变换前后的向量相加，要求两端回到同一形状。Attention 还会沿位置轴比较和汇聚。它们在数据依赖、可并行的轴和访存方式上各不相同。画图时若只标一个“算子盒子”，会看不出哪些量可以独立算、哪些地方必须归约。

这个区分是读下一篇单层结构的钥匙：看到 `2560→10240→2560`，要问中间为何变宽、怎样回到残差；看到 `S×S`，要问位置之间何时开始通信。后面讨论 Prefill、Decode 和片上存储，也都从这些轴的变化出发。
