# 换一个 Gemma 4 型号，资源账怎样重算

![不同型号要重算权重、状态与执行路径的概念封面](../assets/generated/cover-18-zh.png)

[11 篇版索引](README.md) · 第 11 篇

沿 E4B 算完输入、Decoder、KV、权重和热预算，很容易想把结果按参数量缩放到另一个 Gemma 4 型号。这样会漏掉结构变化。型号中的 E 指有效计算参数，A4B 指每 token 约激活的参数；两者都不能直接当作完整权重容量。媒体进入主干的方式、稠密或专家计算、上下文上限，也会重新分配硬件开销。

![Gemma 4 五个型号的输入与结构概览](../assets/generated/gemma4-family-map-18-zh.png)

*图 1：按输入能力与主要结构差异组织，不表示性能排序。以下参数口径来自官方模型卡；上下文上限不等于设备实际可部署长度。*

| 型号 | 官方参数口径 | 输入与首先要重算的对象 |
| --- | --- | --- |
| E2B | 约 2.3B effective，含嵌入约 5.1B；35 层、128K 上下文 | 文字、图像、音频；PLE、媒体前端和 KV 仍需计入 |
| E4B | 约 4.5B effective，含嵌入约 8B；42 层、128K | 本系列分析的基线 |
| 12B Unified | 约 11.95B 总参数；48 层、256K | 文字、图像、音频；媒体进入主干的路径改变 |
| 26B A4B | 约 25.2B 总参数、3.8B 激活参数；30 层、256K | 文字、图像；专家权重与路由带宽分开算 |
| 31B Dense | 约 30.7B 总参数；60 层、256K | 文字、图像；更大的稠密主干与视觉前端 |

## 换型号时，先重画哪些路径

**E2B** 与 E4B 的路径最接近：都有 PLE、独立媒体前端和混合 Attention，但层数与具体宽度不同。主干缩小并不让嵌入表、图像或音频前端消失，长上下文 KV 仍随请求存在。可以沿用本系列的核算方法，不能照搬 E4B 的字节数。

**12B Unified** 仍支持三种输入，却不使用 E4B 那种独立视觉、音频编码器路径，而让媒体经较轻投影进入统一 Decoder。于是原来单列的前端计算会转移为更多主干位置及其跨层计算；评估时要重新数媒体输入长度、层内工作和 256K 历史。少一座独立编码器，不足以推出端到端延迟一定更低。

**26B A4B** 是 MoE：共享 MLP 每次运行，Router 在 128 个候选专家中为当前 token 选择 8 个。每 token 的专家乘加只涉及被选中的部分，但完整专家权重要能被装载或按需访问。把 3.8B 激活参数当成总存储会低估容量；把 25.2B 全算作每 token 的稠密矩阵乘又会高估计算。实际吞吐还取决于专家权重所在层级、路由分布、batch 和带宽。

![共享 MLP、Router 与被选中的专家分支](../assets/generated/gemma4-moe-18-zh.png)

*图 2：橙色专家是当步被选中的分支；其余候选没有消失，仍需要可访问的权重存储。*

**31B Dense** 没有按 token 选部分专家的计算口径；更大的稠密主干沿固定路径运行。它支持图像，没有 E4B 的原生音频路径。权重、视觉前端和 256K 上下文下的 KV 都需重新算，再放进目标设备的容量、带宽和稳态功耗边界。

## 生成策略还会改变执行日程

Gemma 4 的配套草稿模型可用于推测解码（MTP）：较小模型先顺序提出若干候选，目标模型把它们作为已知输入一次验证，接受连续前缀并在拒绝处修正。它尝试减少昂贵的目标模型串行前向，代价是草稿计算、调度与可能被拒绝的候选。接受率低时未必更快；收益必须连同草稿耗时、验证耗时和端到端延迟测量，不能算进任何型号的固有性能。

![草稿候选与目标模型批量验证的流程](../assets/generated/gemma4-mtp-18-zh.png)

*图 3：流程示意，候选接受与修正需按实际推测解码算法实现。*

最终选型先固定任务：文字、图像或音频，输入输出长度、batch、并发及延迟目标。再针对具体型号分别核对**完整静态权重**、**随请求增长的状态**、**每阶段的计算与搬运**、**持续运行的功率和温度**。E4B 给出的价值是一套拆账方法；换型号时，数字和路径都要重新代入。
