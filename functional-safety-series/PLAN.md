# 《芯片功能安全：从原理到 IP 实战》系列规划

**状态：30 章中文主线初稿已写；本文仍为内部编辑计划。** 系列从故障如何传播讲到安全机制、SoC 集成和验证证据，补上 NVM 与模拟采样的物理边界，再把安全设计、分析、文档与评估交付串成完整工程链。目标读者是跨方向的芯片研发工程师；每篇先回答一个具体问题，再决定需要多少标准背景、RTL、图或数据。

## 系列主线

故障与风险 → 故障模型 → 安全机制与 CBB/IP → SoC 架构 → 故障注入与验证 → 分析和需求追踪 → AI 辅助研发。

原构想为五个单元、20 章；ECC 固定码字风险、LBIST、E2E Protection、故障分类、NVM、模拟/混合信号链，以及 TSC/IP LRS、DFMEA/FTA、Safety Manual、Safety Case/评估等独立成章后，共六个单元、30 章。原先的篇幅比例只是早期构想，现以每篇的具体问题和证据成熟度安排内容。前 29 章也应在确有材料时说明 AI 参与的具体环节，避免到收官篇才突然引入 AI。

以下 IP、工具及演示均为**候选案例**。现有文章或参考工程可以提供线索，但其功能、安全属性、指标与公开范围必须逐项核对；计划中的模块不得写成已经实现或达到某项 ASIL 的产品。公开文章须自包含，不要求读者访问内部工程。

## 写作与发布顺序

1. **先做共同案例。** 为 EP01–04 定义同一个可解释的教学系统、故障边界和术语表，让后续文章可以递进；各篇仍须自包含。
2. **优先核实现有素材。** 可从已有 watchdog、比较器、MPU、APB demux、AXI VIP 文章及工程记录寻找 EP08、09、12、14、18 的案例；ECC、SRAM controller、LBIST、E2E、error manager、NVM、ADC、SafeSight 等先列素材缺口，不按名称推定已有实现。
3. **按证据成熟度排产。** EP05–21 的机制篇先确认设计、配置、仿真/注入记录和可公开图；EP22–29 待物理链路、工作产品与系统级证据足够后再决定写实测集成还是明确的教学架构。EP30 以此前实际完成的流程收束。
4. **每期独立交付。** 正文使用仓库现有的根目录文章文件夹约定：`<slug>/README.md` 与 `<slug>/README.en.md`，两版完整、自包含且互链。制作对应语言的独立封面和必要讲解图，维护来源记录与根目录索引。本文保存在独立的 `functional-safety-series/` 文件夹，仅用于系列规划；不预建 30 个空文章目录或空正文。
5. **发布前核对。** 校对中英文的技术事实、数字、图文关系与术语；区分真实测试、估算、假设及概念图；清理私有工程入口和内部编辑路径。运行内容检查后再做人工技术与发布审阅。
