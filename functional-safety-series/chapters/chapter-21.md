# 21｜一条 Safety Goal 如何追到 RTL 和测试？

[返回系列索引](../INDEX.md) · 中文初稿

一份 Safety Goal 写着“特定错误不得导致失控输出”。设计团队说已经加了 ECC，验证团队说回归全部 PASS。如果两份材料之间没有明确映射，审阅者仍无法判断：ECC 保护的是哪块存储，检测后交给谁，那个“PASS”到底检查了哪条要求。需求追踪的价值，就在于暴露这类看似完成、实际上断开的环节。

## 把抽象要求逐层落地

从系统危险分析得到安全目标后，功能安全需求描述系统应如何避免或控制危险；技术安全需求分配到硬件、软件和系统架构；硬件安全需求再具体到模块。例如“读取控制参数时，若检测到不可纠正数据，正常数据有效信号不得置位，并在规定时间内报告”。这个要求可追到 ECC 解码与响应接口、状态寄存器、软件读取/处理约定，以及对应的故障注入测试。路径中任何一个 ID 若只是换句话重复上一级，却没有新增边界、分配或判据，都不能帮助实现。

中间的 TSC 要说明整条安全架构怎样分工：检测、阻断、报告和最终动作由谁执行，哪些共享资源可能同时伤及这些环节。团队若用 IP FuSa LRS 记录 SRAM Controller 的安全需求，LRS 只写该 IP 可控制和可验证的行为；Error Manager 连接、软件响应与外部供电等条件应明确分配或列为使用假设。第 25 章会沿这条边界展开，系列[全流程地图](../PROCESS-MAP.md)则给出各工作产品的关系。

ISO 26262-5:2018 的硬件安全需求部分要求考虑安全机制属性、故障处理时间、验证条件以及硬件软件接口（HSI）的细化。它还要求硬件安全需求与架构元素建立追踪关系。对工程师来说，这意味着“规定周期内上报”必须有时钟域和计数口径，“软件处理”必须有状态保持、清除顺序和启动条件；这些信息不能被一句“驱动会处理”带过。

## RTM 应能回答变更影响

RTM（Requirements Traceability Matrix，需求追踪矩阵）不只是需求到文件名的目录。它应能指出设计元素、验证判据、执行结果及配置版本。若后续把错误分类从“可纠正”改为“不可纠正”，要检查 RTL、状态接口、软件处理、断言、故障 campaign 与 FMEDA 是否同步变化。若一次测试 PASS 却只看到了 `error=1`，而需求要求阻止坏数据消费，RTM 应暴露这个证据缺口。

沿着前文的不可纠正读错误，可以写出一条**教学示例**链；下表列的是要核查的对象，并非某个项目的完成记录：

| 层级 | 需要写明的内容 | 核查问题 |
| --- | --- | --- |
| 系统要求与 TSC | 不可信参数不得触发正常控制输出；谁负责阻断和受控响应 | 受控动作赶得上最早危险输出吗？ |
| IP 需求与 HSI | 不可纠正时 `valid=0`、错误状态锁存、通知时限及清除语义 | CPU 忙碌或 IRQ 被屏蔽时会怎样？ |
| RTL 与验证 | ECC 解码、输出门控、事件路径；故障注入与端到端检查 | 测试是否真的读到错误地址并观察最终动作？ |
| 分析与交接 | FMEDA 分类、共同依赖、Safety Manual 的集成条件 | 哪些逃逸仍靠 SoC 或整车处理？ |

追踪的终点不是表格齐全，而是每项关键主张都能回到明确要求和可核对证据。表中任一栏缺失，都应显式留下待核查项，不能用一条没有观察点的 `PASS` 填平。

## 一次变更怎样穿过整条链

假设原要求允许不可纠正数据在两个周期内报告，系统架构变化后只能容忍一个周期。修改 ECC RTL 的报警寄存器还不够：HSI 的中断时序、软件读取假设、注入测试的观察窗口、FMEDA 对诊断有效性的判断，以及安全岛的反应预算都可能需要更新。RTM 应让工程师从“一个周期”这条约束出发，找到所有受影响的设计和证据。

可复用 IP 交付还要把“哪些配置经过验证、哪些依赖留给集成者”写在集成资料中。没有这些交接信息，需求链到 IP 边界就断了。

若 IP 按 SEooC 假设开发，这份交接更需要具体：预期使用环境和上层安全需求、哪些失效由 IP 内部检测、哪些需要外部 watchdog/错误管理器、错误输出的时序和锁存语义、启动与周期自检的调用责任、被允许的配置及被禁止的测试/调试模式。还要交代硬件软件接口中谁初始化保护寄存器、谁读取并清除错误、谁在超时后执行动作。集成者应逐项核对这些假设是否在目标 SoC 和 item 中成立；安全手册或集成说明是这种核对的输入，不能替代核对结果。[ISO 26262-11:2018](https://www.iso.org/standard/69604.html)将可复用半导体/IP 的集成资料及安全应用说明作为专门议题。
