# 07｜安全 SRAM 控制器除了 ECC 还需要什么？

[返回系列索引](../INDEX.md) · 中文初稿

把 ECC 解码器接到 SRAM 读口，距离一个可用于安全相关功能的存储子系统还有一段路。系统访问的是地址和事务，不是一段孤立的数据。若写错地址，正确的 ECC 码字也会被放进错误位置；若错误状态无法随事务返回，上层软件可能只看到一次“正常读”。因此，SRAM 控制器要把数据完整性、地址、维护和报告放在同一条访问路径中设计。

## 正常访问与错误访问都要定义

一次写入经过地址检查、写数据编码和阵列访问；一次读取经过取数、解码、可能的纠正以及响应返回。控制器需要明确：可纠正错误是返回修正后的数据并附状态，还是要求上层重试？不可纠正错误时，`valid`、响应码与数据如何组合，才能避免下游误把坏数据当作正常值？这些选择没有通用答案，取决于总线协议和系统要求，但接口语义必须可测试。

存储阵列里的永久错误会反复触发纠正。Scrubbing 定期读出、检查，必要时回写修正值，可减少错误累积的机会；它会与正常读写竞争端口，也有自己的计数、暂停和异常处理问题。MBIST 主要面向存储阵列测试，BISR/repair 涉及坏单元替换与冗余资源。它们解决的问题、运行阶段和实现代价不同；某控制器名为“safety SRAM”，并不意味着这些功能全部具备。

## MBIST 要回答 ECC 没回答的问题

ECC 在读出一个码字时检查其一致性；MBIST 则主动对存储阵列执行规定的读写序列。以 March 类测试为例，测试控制器按地址方向写入、读取并核对不同数据背景，目标可以包括 stuck-at、转换故障、部分地址译码和单元耦合故障。具体能覆盖哪些故障，取决于测试算法、宏结构和故障模型，不能把一次“MBIST PASS”理解成阵列所有运行期故障都已排除。

启动测试通常会改写被测存储内容，因而要先决定该 SRAM 此时是否保存关键状态，测试结束后又由谁重建数据与 ECC。运行期测试若要分 bank、分段执行，还要处理业务访问仲裁、测试时长和被测区域暂时不可用；只有确实支持非破坏性或在线测试的实现，才能这样描述。测试控制器、地址发生器、比较器和 fail 状态本身也可能失效，集成时至少需要检查启动条件、超时、失败锁存及错误上报路径。

BISR/repair 常在制造测试或启动测试发现缺陷后，用冗余行/列替换坏位置。修复可以提高可用率，却不自动提高运行期诊断覆盖；还需核对修复信息的保存和装载、错误 repair 映射、修复后 ECC 地址绑定，以及正常访问与 MBIST 是否看到同一逻辑位置。若安全分析把周期测试作为潜伏故障诊断，应给出测试间隔与故障检测时间的关系；出厂一次性测试不能直接记作运行期诊断。

若故障模型包含相邻单元同时翻转，存储宏是否做了物理位交织就直接影响 ECC 的有效性。控制器集成时应取得宏的物理单元到逻辑码字映射、交织距离及多位翻转分析，确认校验位也在保护设计内；随后核对修复配置是否改变映射，以及 MBIST、错误注入和巡检访问所看到的地址与 ECC 码字如何对应。控制器 RTL 中加入 ECC，无法代替存储阵列的物理交织。第 5 章的四码字示意说明原理，实际结论仍取决于选用的宏。

完整码字被读成全零或全一也要列入接口故障模型。普通 ECC 的零 syndrome 不足以排除“错误地读到了另一个合法码字”；若所选宏或控制器提供 All-X 检测，应说明它检查哪些位、哪些地址和哪些运行状态。若 ECC 编码包含当前地址，集成时还要核对使用的是 CPU 地址、控制器局部地址还是宏内部地址，以及 bank、别名、地址重映射与修复后是否仍一致；固定 bias 对一个地址有效，不保证所有地址都排除了危险码字。初始化流程须在允许安全相关读取前建立有效的数据与校验位；不能把未初始化地址恰好读出零 syndrome 当作初始化完成。第 6 章给出检查这类地址相关反例的方法，实际 IP 要用自身 ECC 矩阵和地址映射复核。

## 管理接口也属于保护路径

为了验证 ECC 与报告机制，工程上可能提供错误注入接口。它若能在正常运行中被意外触发，就会引入新的风险；所以注入使能、地址范围和清除过程也需要约束。错误计数要区分“同一位置反复读到一次故障”和“多个独立故障”，否则计数的系统含义容易被误读。最终，控制器需要把可纠正和不可纠正事件交给 Error Manager，并保留足够信息让系统选择响应。

因此，审阅一颗实际 SRAM Controller 时，最好按功能、配置和验证证据逐项核对。ECC、MBIST、repair 与故障报告各有独立边界；控制器提供其中一项，并不能推出其余机制也已具备，更不能直接推出诊断覆盖率。

**交付给集成者的内容。** 可复用 SRAM IP 若面向安全相关设计，接口说明还需写明哪种配置经过验证、错误输出需要怎样的外部处理、上电和运行时测试由谁执行。ISO 26262-11:2018 对 IP 的集成资料特别强调使用假设、推荐配置、故障报告、自检和硬件软件接口。它提醒我们：一份 RTL 与一张 block diagram 还不能让集成者正确使用 IP。反过来，集成者也不能把供应方的假设原样当成已验证事实。

## 部分写与巡检会改变问题

按字节使能写入时，控制器可能先读旧字、合并新字节、重新计算 ECC，再写回阵列。若旧码字已不可纠正，继续合并可能把不可信数据重新编码为“正确”码字。硬件应拒绝、报告还是由软件恢复，必须事先约定。读改写还会遇到其他 master 并发访问；scrubber 的回写若缺少仲裁，可能覆盖正常写入。

验证不能只列整字读写与一位错误。还应覆盖部分写叠加旧错误、巡检与业务竞争、复位中断巡检，以及错误状态清除时再次报错。对相邻单元多位翻转，先依据宏的物理映射确定它影响几个码字，再分别检查每个码字的纠错结果、事件计数和系统告警；仅在同一逻辑地址上翻转两位，测不到物理交织的保护效果。还需分别注入完整码字全零/全一与正常写入全零/全一数据，避免把两种情形混为一谈。

MBIST 的验证也应至少区分测试本身未完成、阵列缺陷被检出、测试比较器失效，以及测试结束后内容恢复错误。记录算法和目标故障模型后，再讨论故障覆盖率；测试模式数或测试时间本身不是覆盖率。
